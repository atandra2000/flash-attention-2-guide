01

The operation

Scaled dot-product attention, exactly.

definitionone headshape ledger

For one head with sequence length N and head dimension d, the inputs are three matrices: a query matrix Q ∈ ℝN×d, a key matrix K ∈ ℝN×d, and a value matrix V ∈ ℝN×d. Each row of Q is the “what this token is looking for” vector, each row of K is the “what this token offers” vector, and each row of V is the payload that gets re-weighted. The output is a single matrix O ∈ ℝN×d where row i is a convex combination of value rows, with weights determined by the similarity of query i to every key.

Start one step earlier: where Q, K, and V come from

The model does not receive queries and keys from the tokenizer. It first turns each token into a learned residual-stream vector. Stack those vectors as X ∈ ℝN×dmodel. One attention head applies three learned linear projections: Q = XWQ, K = XWK, and V = XWV, where every projection has shape W ∈ ℝdmodel×d. The three projections let one token ask a question, advertise what it matches, and offer information to copy using different learned coordinate systems.

1 / represent

XOne row per token: the current meaning of each position.

2 / project

Q, K, VThree learned views of the same token vector, each with a different job.

3 / retrieve

O = PVEach query mixes value rows according to query–key compatibility.

definition · scaled dot-product attention S = Q KT√d   , P = exp(S + M)1T exp(S + M)   , O = P V

Reading it row-by-row, the three maps are: (1) a similarity matrix S ∈ ℝN×N whose entry Sij measures how compatible query i is with key j; (2) a row-softmax that turns each row of S into a probability distribution, with an optional additive mask M ∈ {0, −∞}N×N (e.g. causal); and (3) a weighted average of value rows using the probabilities.

Why 1/√d ?

If q, k are independent components with zero mean and unit variance, then the dot product q · k = Σi=1d qi ki has variance d. Without a scale, the logits grow in magnitude with dimension, and softmax saturates: one entry approaches 1, all others approach 0. The gradient through softmax then vanishes and training stalls. Dividing by √d keeps the score variance near 1 regardless of d, which keeps softmax in its well-conditioned regime.

derivation · score variance under scale Var(Sij)1 = Var(qi · kj)d = d · Var(qi) · Var(kj)d = 1

The quadratic bottleneck

Every token attends to every other token. The N × N intermediate S (and the equal-sized P) is the source of attention’s expressiveness and its cost. For N = 4 096, that is 1.6 × 107 entries per head. For N = 65 536, it is 4.3 × 109. The output is only N × d, but the N × N intermediates dominate memory traffic. The mathematical definition does not require materializing those intermediates; they are an artifact of writing the operation as three sequential dense passes.

Mask, dropout, and the contract on exactness

A causal language model uses a mask M with Mij = 0 for j ≤ i and Mij = −∞ otherwise, so position i cannot see future tokens. exp(−∞) = 0, so masked columns contribute nothing to the softmax. Attention dropout (when used in training) multiplies the post-softmax P by an independent Bernoulli mask; the same mask must be re-applied on the backward pass, which is why implementations deterministically regenerate it rather than persist the full probability matrix. The contract throughout this guide is that “exact” means the same mathematical operation as a triple-pass reference — bitwise equality is not the target, only equivalence of the floating-point result up to normal rounding error.

02

The constraint

The memory wall, not the FLOP count.

HBMarithmetic intensitylower bound

Matrix multiplication is highly optimized on a GPU. The problem with the naive decomposition is the data-movement shape: compute S, write it to HBM; read S for softmax, write P; read P and V for the final product. Both S and P are N × N, and the round-trips to HBM dominate runtime for realistic N.

Follow one score tile’s lifetime

“Materialize” means give an intermediate a long-lived address in HBM. A conventional implementation cannot hand the scores from the first GEMM directly to the softmax kernel, because they are separate GPU launches. It must write the score tile out, then load it again later. The same thing happens to the probabilities before the PV GEMM. FlashAttention changes the lifetime, not the answer: a score tile exists only long enough to update m, ℓ, and o, then its storage is reused for the next tile.

Naive / score

S: HBM writeQKT produces N² scores, then the next kernel must load them back.

Naive / probability

P: HBM writeSoftmax produces another N² matrix before PV can consume it.

Flash / tile

SRAM onlyScore and local weights update a small row state, then disappear before HBM sees them.

Arithmetic intensity: the only metric that matters here

Arithmetic intensity is the ratio of floating-point operations to bytes of HBM traffic. A kernel is compute-bound when its intensity exceeds what the hardware can sustain; it is memory-bound when the HBM bandwidth is the constraint. The naive attention has Θ(N²d) FLOPs and Θ(N²) bytes of intermediate traffic, so its intensity is Θ(d) — about 64–256 FLOPs/byte. On an A100 that number is well below the ridge point of the roofline, so naive attention spends most of its time waiting for HBM.

lower bound · intensity of naive attention FLOPsHBM bytes = Θ(N²d)Θ(N²) = Θ(d)1   ,   with d = 64, 128, 256

The GPU memory hierarchy

Think of GPU memory as a pyramid, smaller and faster toward the bottom:

  • HBM (global memory): 80 GB on A100, 3.35 TB/s of bandwidth, ~400 cycles of latency. Large, but slow relative to on-chip storage.
  • L2 cache: 40 MB on A100, faster than HBM, still shared across all SMs.
  • Shared memory: ~100 KB usable per SM on A100, programmer-managed, on-chip, ~100× faster than HBM.
  • Registers: 64 KB per SM, private to each thread, the fastest level but extremely limited.

FlashAttention’s structural choice is: once a tile of Q, K, or V is loaded into shared memory, that tile participates in many multiply-accumulate operations before being evicted. Each HBM byte amortizes more FLOPs, the arithmetic intensity rises, and the kernel moves toward the compute-bound side of the roofline.

Why not larger tiles?

Shared memory is a fixed budget per thread block. A tile of size Br × Bc for the partial scores, plus Br × d for Q and Bc × d for K and V, must all fit in on-chip storage simultaneously. The published choice is Br = 64, Bc = 64, d ∈ {64, 128, 256}. Larger tiles would exceed capacity and force spilling; smaller tiles would underutilize the tensor cores.

03

The invariant

Online softmax makes tiling exact.

translation invarianceassociative mergestability

Softmax looks global: each row probability needs the sum of exponentials across the entire row. Stable softmax subtracts the row maximum first, and that maximum — together with the normalizer — can be maintained incrementally. For each query row, retain just three pieces of on-chip state: the running maximum m, the normalizer ℓ, and the unnormalized output numerator o.

What the three numbers remember

Imagine reading a long row of scores through a narrow window. You do not need to remember every earlier score. You need only: the best score seen so far (m), the total probability mass in the current coordinate system (ℓ), and the value-weighted mass (o). The final division o / ℓ converts that unnormalized weighted sum into the ordinary weighted average. A new tile never changes the old tokens; it merely expresses their contribution in the new tile’s numerical reference frame.

definition · online softmax update for one K/V block

m′=max(m, maxj ∈ J Sj)
ℓ′=em − m′ · ℓ + Σj ∈ J eSj − m′
o′=em − m′ · o + Σj ∈ J eSj − m′ · vj
O=o / ℓ (after all blocks)

When a new block raises the maximum, multiply the old accumulator by the matching rescaling factor. That one correction preserves every old contribution at the new numerical reference point. No approximation is introduced: the result is mathematically identical to a full-row softmax. Floating-point bits may differ from another valid evaluation order because additions are reassociated.

Derivation: why rescaling is exact

Start with the standard stable softmax for a full row. Let m = maxi Si. Then

derivation · stable softmax exp(Si)Σj exp(Sj) = exp(Si − m)Σj exp(Sj − m)   , with all exponents ≤ 0

Now imagine having processed the first j elements of a row and stored three numbers:

  • mj — the maximum of the first j scores.
  • ℓj = Σi ≤ j exp(Si − mj) — the normalizer referenced to that running maximum.
  • oj = Σi ≤ j exp(Si − mj) · vi — the unnormalized weighted sum of values.

When the next block arrives with new maximum mnew, two cases can occur:

  1. mnew ≤ mj: the running maximum already dominates. Rescale only the new contributions by exp(mnew − mj) ≤ 1.
  2. mnew > mj: the new maximum is larger. Rescale all old contributions by exp(mj − mnew) < 1 so they become referenced to mnew, then add the (already-scaled) new contributions.

key identity · telescoping rescale exp(mold − mnew) · exp(mnew − mlatest) = exp(mold − mlatest)

Rescaling is associative. No matter how many times the running maximum is updated, the final contributions are all referenced to the same value — and the resulting o / ℓ is mathematically identical to a one-shot softmax over the full row. Floating-point implementations can differ by normal rounding error because they add terms in a different order.

Numerical stability

Without max-subtraction, exp(100) overflows and exp(−100) underflows to zero. By always subtracting the current running maximum, every exponent lies in (0, 1]; the rescaling factors are in (0, 1]; and the intermediate o is a sum of non-negative terms, so no overflow occurs. In fact, the per-tile computation tends to be more stable than the one-shot baseline: catastrophic cancellation in the exponent is reduced because each tile’s local maximum is small in magnitude relative to the global maximum, and the rescaling factors smooth out the dynamic range.

Why associativity unlocks parallelism

The merge rule is associative: combining two independent states (ma, ℓa, oa) and (mb, ℓb, ob) gives the same result regardless of whether they were produced by the same block, different blocks on the same SM, or different GPUs communicating over the network. The merge itself is

merge · two partial states

m=max(ma, mb)
ℓ=ema − m ℓa + emb − m ℓb
o=ema − m oa + emb − m ob

This is the structural reason FlashAttention scales: the same merge composes within a block, across blocks, across SMs, and across GPUs. The Foundations chapter proves the merge is associative and that it preserves the softmax exactly.

Exactness boundary. A floating-point kernel may differ from another valid evaluation order by normal rounding error. It computes the same mathematical attention operation, not a low-rank, sparse, or linear-attention substitute.

04

The sequel

FlashAttention-2: better parallelism and work partitioning.

FlashAttention-1 already minimizes HBM traffic — the kernel is asymptotically optimal in IO. FlashAttention-2 then targets the remaining gap to peak GEMM throughput. Its paper describes three changes: reduce non-matmul scalar work, schedule independent query blocks from one long head across more thread blocks, and divide work across warps so they communicate less through shared memory.

1. Keep tensor cores busy

GPU matrix units are dramatically faster than scalar floating-point instructions. FA-2 therefore keeps the output in the unnormalized form already used by this guide: o = Σ exp(s − m)v. It rescales only when a tile changes the running maximum, and divides by ℓ once at the end instead of repeatedly normalizing the partial output. It also saves one row-wise L = m + log ℓ value for backward rather than separate m and ℓ values. The output is unchanged; the instruction mix shifts toward tensor cores.

amortization · scalar ops per Q-tile scalar FLOPstensor-core FLOPs = O(d)O(Bc · d) = O(1)Bc   , FA-2 maximizes Bc within the shared-memory budget

2. Sequence-length parallelism

FA-1 primarily exposes one thread block per batch–head pair. If batch × heads is smaller than the GPU’s SM count, many SMs have no block to execute. FA-2 adds sequence-length parallelism by assigning independent outer-loop query blocks to separate thread blocks. Each block owns a disjoint slice of output rows and streams all needed K/V tiles, so forward blocks do not need to merge partial rows. Long sequences now create enough independent Q blocks to occupy the machine even when the batch is small.

3. Sliced-Q work partitioning

A thread block contains several warps (typically 4 on A100). In FA-1, every warp cooperated on the same output rows, which required shared-memory reductions. FA-2 assigns each warp a different slice of query rows (sliced-Q). Warps still share the same K/V tile loaded into shared memory — but their output rows are disjoint, so no cross-warp reduction is needed. The shared-memory traffic inside a block drops to the bare minimum.

comparison · FA-1 sliced-K vs FA-2 sliced-Q
FA-1warp owns K/V slice·cross-warp reduce over partial outputs
FA-2warp owns Q slice·independent outputs, no shared-memory reduction

01 / arithmetic

Keep tensor cores busy

Rescaling and softmax work is batched so each tensor-core matmul is larger; scalar work shrinks to a small fraction of runtime.

02 / blocks

Parallelize one long head

For small batch × head counts, assigning one block to a row range can leave the GPU under-occupied. FA-2 adds sequence-length parallelism.

03 / warps

Use sliced-Q work

Warps own different query slices while sharing K/V. Their output slices are independent, avoiding reductions through shared memory used by the sliced-K style.

Kernel & backward

What the kernel owns, and how gradients flow back.

A

Thread block

Loads one K/V tile, takes a Q tile or slice, and keeps block-local intermediate state on chip.

B

Warp

A group of 32 CUDA threads. FA-2 gives warps independent Q output slices, reducing synchronization and shared-memory exchange.

C

Tensor cores

Specialized matrix-multiply hardware accelerates the QKT and PV-shaped products. Shape and datatype affect how effectively they are used.

D

Registers + shared memory

Hold fragments, scores, softmax statistics, and tiles just long enough to avoid round-trips to HBM.

The forward pass, step by step

For one query block Qr ∈ ℝBr×d and the stream of K/V blocks (Kc(j), Vc(j)) ∈ ℝBc×d:

  1. Load Q tile: each thread block loads Qr from HBM into shared memory.
  2. Loop over K/V tiles. For each j:
    • Load Kc(j) and Vc(j) into shared memory.
    • Compute Sr,c = Qr Kc(j)T / √d using tensor cores.
    • Apply the mask: Sij ← Sij + Mij (where Mij ∈ {0, −∞}).
    • Update the running maximum: m′ = max(m, maxc Sr,c); rescale the old o and ℓ by em − m′.
    • Compute Pr,c = exp(Sr,c − m′); update ℓ ← em − m′ ℓ + Σc Pr,c.
    • Accumulate the output: o ← em − m′ o + Pr,c Vc(j).
  3. Final normalization: Or = o / ℓ; write Or and the per-row log-normalizer L = m + log ℓ to HBM for backward.

algorithm · forward pass, one Q-block 

init:   m = −∞,  ℓ = 0,  o = 0
for each K_c, V_c block j:
    S = Q_r · K_c^T / √d
    S += M                                  # causal mask
    m_new  = rowwise_max(m, S)
    P      = exp(S − m_new)                  # all ≤ 0
    ℓ      = exp(m − m_new) · ℓ + rowsum(P)
    o      = exp(m − m_new) · o + P · V_c
    m      = m_new
O_r = o / ℓ                                  # write to HBM

The backward pass

The backward pass computes ∂L/∂Q, ∂L/∂K, ∂L/∂V from ∂L/∂O. The chain rule gives three identities:

Backpropagation in plain language

Suppose the loss says that output row Oi should have moved in some direction. That signal first asks which value rows contributed to Oi: those contributions form ∂L/∂V. It then asks which attention weights made the mixture too large or too small: that is the signal through P and its row-wise softmax. Finally, it asks which query–key dot products created those weights. That produces ∂L/∂Q and ∂L/∂K.

The important systems point is that this explanation only needs a score tile and its local softmax at one time. Once a backward tile has regenerated its scores from the resident Q/K/V tiles and the saved log-normalizer, it can accumulate the corresponding slices of ∂Q, ∂K, and ∂V, then discard the tile. The full probability matrix is a convenient algebraic picture, not a storage requirement.

definition · gradient of attention

∂L/∂V=PT · (∂L/∂O)
∂L/∂S=P ⊙ ( (∂L/∂O) · VT − rowsum( (∂L/∂O) ⊙ O ) ⊙ 1T P )
∂L/∂Q=(∂L/∂S) · K / √d
∂L/∂K=(∂L/∂S)T · Q / √d
where ⊙ is element-wise multiplication, and the rowsum term is the softmax Jacobian.

The problem: these formulas all depend on the N × N probability matrix P. Storing P for N = 65 536 needs ~16 GB per head — prohibitive. FlashAttention does not save P; it recomputes the per-tile softmax during backward, using the saved row-wise L = m + log ℓ from forward to recover stable normalization.

cost · recomputation vs storage

storageO(N²)· HBM traffic, dominant at large N
recomputeO(N²d)· FLOPs, dominated by cheap tensor-core matmuls

The trade is favorable when the kernel is memory-bound, which is exactly the regime where attention is the bottleneck. The FLOP overhead of recomputation is roughly 33% more FLOPs than a saved-probabilities backward, but the HBM savings are Θ(N²) bytes eliminated per layer per step.

Causal structure halves the FLOPs

For causal attention, the upper triangle of S is masked to −∞ before softmax and therefore contributes zero. The kernel exploits this by skipping the upper triangle: only the lower triangle is computed, halving the FLOPs of the Q KT matmul. The gradient ∂L/∂S inherits the same structure, so the same skip applies on the backward pass.

Block-diagonal gradient structure

The gradient with respect to the score matrix is not block-diagonal in general, but for causal attention it inherits the lower-triangular sparsity. The block-level accumulation pattern is the mirror of the forward: forward accumulates O; backward accumulates ∂L/∂Q, ∂L/∂K, ∂L/∂V. Each block writes once to HBM after the inner loop finishes, so the inner accumulation lives in shared memory.

Checkpointing trade-off

Standard PyTorch attention saves the N × N probability matrix for backward, costing Θ(N²) memory. FlashAttention recomputes it from Q, K, V in Θ(Nd) memory. For N = 65 536, d = 128: saving probabilities needs 16 GB; recomputation needs ~100 MB. The FLOP overhead is ~30%, but the memory savings enable much longer sequences.

Masking & dropout

Causal masks can skip entire tile regions. Attention dropout must reproduce the same mask during backward, so implementations use deterministic random-number bookkeeping (a per-row seed) rather than storing every probability.

Backward pass

The backward pass does not need a saved N × N probability matrix. It recomputes blockwise quantities from Q, K, V, the output gradient, and the saved per-row log-normalizer L = m + log ℓ from the forward pass. Extra compute, dramatically less HBM traffic.

06

Beyond the basics

Extensions and variants.

sparsepagedFP8ringcontext

Block-sparse attention

FlashAttention can skip blocks that the mask marks as irrelevant. For causal attention, the upper-triangular blocks are never computed. For sparse patterns (e.g. Longformer’s sliding window plus a few global tokens), the kernel loads only the non-zero blocks. The online softmax state still accumulates correctly: missing blocks simply contribute zero. The result is not the same mathematical operation as dense attention — it is a masked variant that is exact for that mask.

Multi-query and grouped-query attention

In multi-query attention (MQA), all query heads share one K/V head. In grouped-query attention (GQA), groups of query heads share a K/V head. FlashAttention-2 handles both by loading each K/V tile once and reusing it across multiple Q tiles. The K/V cache bandwidth at inference drops by a factor equal to the number of queries sharing each K/V head (often 4–8 in modern LLMs).

reduction · K/V cache bandwidth bandwidth(GQA-g)bandwidth(MHA) = 1g   , where g = number of query heads per K/V head

Paged attention (vLLM)

For autoregressive inference, the KV cache grows with sequence length. vLLM organizes the cache into fixed-size pages and uses a page table to map logical token positions to physical pages. FlashAttention can operate on non-contiguous K/V pages by gathering tiles through the page table, enabling memory-efficient batching of sequences with different lengths.

FP8 / double quantization

FlashAttention-3 adds native FP8 support: Q, K, V are quantized to FP8 before the matmul, and the inner accumulation stays in higher precision. The tiling strategy is unchanged; only the load/store and matmul dtypes shift. Quantization error is typically small compared to the softmax’s numerical-stability margin (a few ULPs).

Ring attention for sequence parallelism

When a single GPU cannot hold the full sequence, ring attention partitions the sequence across multiple GPUs. Each GPU holds a shard of Q, K, V and communicates in a ring topology. The algorithm: each GPU computes local Q KT, then passes K, V to the next GPU while receiving from the previous. After G − 1 steps (for G GPUs), every GPU has seen all K/V tiles. The online softmax state merges across GPUs identically to the single-GPU case — the merge rule is associative, so ring reduction is just a distributed instance of the same operation.

Context parallelism (CP)

For ultra-long contexts (1M+ tokens), context parallelism splits the sequence across GPUs at the token level. Unlike tensor parallelism (which splits within a layer), CP splits across the sequence dimension. Each GPU runs a FlashAttention kernel on its local shard, then all-reduces the softmax statistics (m, ℓ, o). Recent work achieves near-linear scaling to 1024 GPUs for 10M-token sequences.

Research frontier

  • FlashDecoding: further parallelizes the reduction across warps for inference.
  • PagedFlashAttention: integrates with paged KV caches for serving.
  • FlashAttention-3: FP8, async TMA copies, warp-specialization for H100.
  • Triton implementations: high-level kernels approaching hand-written CUDA performance.
  • HiP attention: hierarchical paging for trillion-token contexts.
  • Minference: dynamic sparse patterns that adapt to attention heads.

When to use what

  • CuDNN attention: short sequences (N ≤ 384), large batches. Optimized for the compute-bound regime.
  • FlashAttention-2: medium to long sequences (N ≥ 1K), any batch size. The all-rounder.

  • Linear attention: extreme sequences (N ≥ 128K) where even FA-2 is too slow; accepts approximation.

Trade-offs

  • Exact vs approximate: FlashAttention is exact; linear attention (Performer, RetNet) approximates.
  • Memory vs compute: sparse attention saves memory but may lose accuracy; FA-2 saves memory exactly.
  • Training vs inference: FlashDecoding optimizes for autoregressive decode; FA-2 optimizes for prefill.
  • Single-GPU vs multi-GPU: ring attention and context parallelism scale beyond single-GPU memory.
08

Mathematical foundations

Why the math works.

Every claim the chapters make reduces to a small number of statements. This chapter proves them in one place, in the order a careful reader needs: softmax is invariant under translation; the merge of two online-softmax states is associative; the IO lower bound matches what FlashAttention achieves; the recomputation strategy is FLOP-cheap and memory-free; and the kernel’s claimed exactness is correct under standard floating-point assumptions.

theorem · translation invariance of softmax

For any vector x ∈ ℝn and any scalar c ∈ ℝ, softmax(x + c · 1) = softmax(x).

exp(xi + c)Σj exp(xj + c) = exp(xi) · exp(c)Σj exp(xj) · exp(c) = exp(xi)Σj exp(xj) ∎

The factor exp(c) cancels in numerator and denominator. Subtracting the running maximum is therefore a free degree of freedom that the algorithm can use to keep all exponents in (−∞, 0].

theorem · associativity of online state merging

Let (ma, ℓa, oa) and (mb, ℓb, ob) be online-softmax states from disjoint score sets. Define the merge as in chapter 03, with m = max(ma, mb), ℓ = ema − m ℓa + emb − m ℓb, and o = ema − m oa + emb − m ob. Then the merge is associative: merging A and B, then C, equals merging A with the merge of B and C.

Each merge normalizes both inputs to the same reference maximum m, sums the normalized contributions, and emits a new maximum. Composition of two such merges is again of the same form: the final state has the correct maximum (the max of all inputs) and the correct total normalizer and numerator, by linearity of the rescaled sum. The order of additions is independent of the merge order. ∎

Consequence: the result of streaming softmax over a row does not depend on the order in which tiles are processed, the number of warps, the number of blocks, or the number of GPUs. FlashAttention’s correctness under all of FA-1, FA-2, sequence parallelism, ring attention, and context parallelism follows from this single statement.

theorem · IO lower bound and FlashAttention’s optimality

Any correct attention algorithm that reads Q, K, V from HBM and writes O to HBM performs at least Ω(N²d / M) HBM accesses, where M is the on-chip memory capacity. FlashAttention matches this bound to within a constant for d ≤ M / B.

The total useful output is Nd elements; the total useful input is 3Nd. Any kernel that does not persist the N × N intermediate must, by the time the last row of O is written, have read each row of K and V that contributes to it. The IO cost of streaming K and V is 2Nd; the cost of streaming Q is Nd; the cost of writing O is Nd. The lower bound is therefore Ω(Nd) in the ideal case. With finite on-chip memory M, each tile of size B must be loaded and reused; the number of reuses is N/B, giving the classical Ω(N²d / M). FlashAttention loads Q once, streams K/V in N/B tiles per row, and produces O in one pass — exactly the bound. ∎

No algorithm can reduce HBM traffic below this without changing the mathematical operation (e.g. sparse, low-rank, or linear attention). That is what “exact” means in the name.

theorem · recomputation is a free trade at long N

Forward attention costs 2N²d FLOPs. Backward attention with saved probabilities costs 4N²d. Backward with recomputation costs 6N²d. The 50% extra FLOPs are negligible compared to the HBM traffic saved: Θ(N²) bytes of probability storage eliminated per layer per step.

Standard backward needs 3N²d matmul FLOPs (the three gradient terms) plus pointwise ops; saved probabilities turn the ∂L/∂S computation into a pointwise op. Recomputation re-runs the forward softmax in Θ(N²d) FLOPs and the matmuls are then identical. The +2N²d extra FLOPs are dominated by the N² HBM savings in the memory-bound regime. ∎

General checkpointing trades memory for the same reason; FlashAttention is a specialized checkpoint that knows the attention structure and reuses on-chip state across the recompute.

lemma · numerical stability under rescaling

For any sequence of running maxima m(1), m(2), …, m(k) with m(i+1) ≥ m(i) for some subsequence, the cumulative rescale factor after k updates lies in (0, 1], so the accumulator cannot overflow.

Each rescale is exp(−Δm) with Δm ≥ 0, hence in (0, 1]. A product of numbers in (0, 1] stays in (0, 1]. The running normalizer ℓ is a sum of non-negative terms scaled by (0, 1] factors; with max-subtraction every term lies in (0, 1], so ℓ ∈ (0, Bc]. The numerator o is the same rescaled sum against value vectors, bounded by the value magnitude times the row sum. ∎

The complete correctness sketch

Putting the four theorems together: the online softmax state is well-defined at every step (translation invariance), the merge is associative (so reductions compose), the recomputation strategy is FLOP-cheap (so backward is not a bottleneck), and the rescaling never overflows (so numerics stay clean). The kernel implements the merge in shared memory, parallelizes it across warps and blocks via associativity, and respects the IO lower bound by streaming tiles. That is the proof of FlashAttention.

What FlashAttention is not

It is not a sparse method (no scores are dropped). It is not low-rank (no projections of the score matrix are taken). It is not linear attention (the softmax is exact, not a feature map). It is not FlashAttention-3 (no FP8, no TMA, no warp specialization; those are separate techniques). The exact tile sizes, the warp work assignment, and the BF16 path are implementation details of the paper, not the algorithm.
